# Documentation Skill: Support Ticket Management System

This skill governs the creation and maintenance of documentation for the Support Ticket Management System. AI-generated documentation must strictly adhere to the following project-specific practices:

## 1. Source of Truth

All documentation must be consistent with the official specifications:

- `spec/requirements.md`
- `spec/architecture.md`
- `spec/data-model.md`
- `spec/api-contract.md`
- `spec/state-machine.md`
- `spec/ui-flow.md`
- `spec/test-strategy.md`

Do **not** invent or embellish requirements, features, APIs, fields, status transitions, response formats, error codes, or business rules not found in these documents.

## 2. Scope and Alignment

- Only document features and behaviors included in the specification.
- Out-of-scope topics—such as authentication, authorization, deletion (DELETE), notifications, dashboards, and pagination—must **not** be documented, implied, or referenced.
- Always use established project terms, field names, response codes, and status values. Maintain naming conventions as specified.

## 3. Coordination Across Documentation

- When describing an API, state machine, data model, UI, or test strategy, verify alignment with the corresponding spec files.
- If an implementation change occurs, identify which parts of the documentation (API docs, state-transition tables, field lists, etc.) require revision to stay current.

## 4. Requirements vs. Assumptions

- Distinguish clearly between required spec-driven features and any implementation-specific detail or assumption.
- If documentation generated by AI includes information not explicitly covered in the source specifications (e.g., inferred constraints or optional behaviors), clearly flag these items for developer review. Do **not** present such assumptions as confirmed requirements.

## 5. Brevity and Usefulness

- Prioritize concise, actionable, and maintainable documentation. Avoid unnecessary repetition or verbose explanations.
- Ensure every documented detail serves a practical purpose and accurately reflects the approved specifications.

## 6. Specification File Integrity

- Never modify or overwrite the official specification files listed above except when explicitly instructed to do so.

---

Apply these guidelines to all documentation generated or updated for this project. The goal is to maintain a single, accurate, and practical source of documentation that always mirrors the current, approved assignment requirements and system behavior.
